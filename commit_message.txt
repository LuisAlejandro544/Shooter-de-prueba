fix(ci): resolver ModuleNotFoundError 'numpy' en exportador glTF y sanitizacion de nombres UTF-8

- Diagnostico y solucion del fallo en GitHub Actions ('ModuleNotFoundError: No module named numpy'):
  * Causa raiz: El complemento oficial de exportacion glTF 2.0 de Blender ('io_scene_gltf2') requiere obligatoriamente 'numpy' para el empaquetado optimizado de buffers binarios de vertices y esqueletos. En runners headless de Ubuntu ('apt-get install blender'), el entorno Python embebido carece de 'python3-numpy' por defecto.
  * Solucion integral en '.github/workflows/generate-assets-3d.yml':
    - Se agrego el paquete 'python3-numpy' en la instalacion de paquetes de sistema de Ubuntu.
    - Se instalo 'numpy' via pip en el entorno Python 3.11 del runner.
    - Se propaga dinamicamente 'PYTHONPATH' al comando CLI de Blender para enlazar directamente las librerias y modulos compilados.
  * Respaldo defensivo en 'tools/blender/generate_realistic_assets.py':
    - Se inyectan dinamicamente las rutas de 'site-packages' y 'dist-packages' del sistema en 'sys.path' al iniciar la ejecucion del script.

- Correccion en la sanitizacion de nombres de archivos con caracteres especiales o acentos:
  * Se incorporo 'iconv -f utf-8 -t ascii//TRANSLIT' en la generacion de la ruta de salida, permitiendo que prompts como 'ak47 clásica' o 'fusil táctico' se transliteren limpiamente a 'ak47_clasica.glb' sin perderse caracteres ni provocar discrepancias en 'ls'.
